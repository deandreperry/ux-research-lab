# Frontend Developer Interview Guide

**Artifact type:** Portfolio Simulation

## Interview Objective

Learn how frontend developers evaluate learning materials, documentation, component examples, and implementation guidance when building user interfaces.

## Participant Profile

Frontend developers, design engineers, or full-stack developers who regularly implement web interfaces with HTML, CSS, JavaScript, component libraries, or design systems.

## Opening Script

Thanks for participating. I am researching how developers use documentation and examples to make frontend decisions. This is not a test of your technical skill. I am focused on your workflow, expectations, and points of friction.

## Warm-Up Questions

- What kind of frontend work do you do most often?
- Which documentation or learning resources do you rely on?
- How do you usually move from design requirements to implementation?

## Core Questions

- Tell me about a time when frontend documentation helped you move faster.
- Tell me about a time when documentation slowed you down.
- What details do you need before reusing a component or pattern?
- How do you check whether an implementation is accessible?
- What makes an error message useful during local development?
- How do you prefer examples to be structured: conceptual, code-first, task-first, or reference-style?

## Task-Based Prompts

- Find guidance for implementing an accessible modal. What information do you look for first?
- Review a sample lesson or pattern page. What would you trust, question, or skip?
- Explain how you would debug a failed setup step in a beginner CLI lesson.

## Follow-Up Probes

- What did you expect to happen at that step?
- What would you search for next?
- How would you know the solution is production-ready?
- What would make this easier for a new developer?

## Closing Questions

- What is one documentation improvement that would save you time?
- What do teams misunderstand about developer experience?
- What should a research-informed frontend portfolio show?
