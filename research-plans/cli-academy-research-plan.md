# CLI Academy Research Plan

- **Status:** Research proposal; illustrative hypotheses only

- **Decision owner:** Learning-product lead with content design and engineering partners

## Background

CLI Academy is a proposed learning experience that helps beginners build confidence with terminal commands through guided tasks, feedback, and realistic developer workflows.

## Problem Statement

Many learners understand programming concepts but feel blocked by command-line interfaces. Fear of breaking something, unclear error messages, and memorization-heavy tutorials can reduce confidence and slow technical growth.

## Research Goals

- Understand beginner anxiety around terminal usage.
- Identify which CLI concepts create the most confusion.
- Evaluate whether guided practice improves confidence.
- Define feedback patterns that help learners recover from mistakes.

## Research Questions

- What moments make learners feel uncertain or unsafe in the terminal?
- How do learners interpret command output and errors?
- Which learning formats support retention: explanation, practice, or challenge?
- What scaffolding should be removed as learners gain confidence?

## Target Users

- Early-career developers
- Bootcamp students
- Designers learning frontend workflows
- Self-taught learners using Git, npm, and local development tools

## Methodology

| Method | Proposed Sample | Rationale |
| --- | --- | --- |
| Recent-experience interviews | 6 learners with varied recent CLI use | Understand real error, recovery, and abandonment episodes |
| Baseline survey and task | Same participants | Compare confidence with observable strategy rather than using self-report alone |
| Prototype usability sessions | 5–6 eligible learners | Evaluate orientation, feedback, progressive hints, and recovery behavior |
| Delayed follow-up task | Participants who consent to follow-up | Test transfer and retention one week later |

## Product Validation Criteria

- Learners can complete core commands with fewer repeated errors.
- Learners can explain what a command does before running it.
- Confidence ratings improve after guided practice.
- Error messages lead to recovery instead of abandonment.

Record task definitions, denominators, hint use, moderator intervention, and comparable-task performance. Confidence is supporting evidence, not a substitute for observed behavior.

## Recruitment And Sampling

Recruit people with basic HTML/CSS knowledge and limited-to-moderate terminal experience. Include variation in learning path and recent CLI use. Exclude professional developers whose routine terminal expertise would invalidate the beginner tasks. Do not treat students, self-taught learners, and designers as interchangeable during analysis.

## Ethics And Data Handling

Explain recording, incentive, data use, and the intentionally triggered error before consent without revealing the solution. Use a safe sandbox with no access to participant files or accounts. Participants may stop at any time and still receive the stated incentive. Publish only de-identified, consented excerpts.

## Analysis Plan

Code orientation, prediction, interpretation, recovery, help-seeking, confidence change, and conceptual explanation. Separate product-caused errors from participant input mistakes. Compare immediate and delayed performance without implying statistical significance from a small formative sample. Retain cases where reassurance or hints create dependence.

## Communication Plan

Deliver a prioritized lesson-content model, error-state requirements, and decision log to learning design and engineering. Each recommendation should identify the evidence, owner, implementation dependency, and follow-up measure.

## Risks And Assumptions

- The simulation assumes participants have basic computer literacy.
- Learners may overreport confidence after successful tasks.
- Command-line fear may be influenced by prior classroom or workplace experiences.
- Results should be validated over time to assess retention.

## Expected Outputs

- Learner confidence map
- CLI task friction inventory
- Error recovery recommendations
- Lesson sequencing guidance
- Prototype improvement backlog
