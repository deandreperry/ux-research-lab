# CLI Academy: Designing For Confidence And Error Recovery

- **Status:** Planning only; the study has not been run
- **My role:** Research plan, learning tasks, interview and test design, synthesis, and measurement
- **Product stage:** Concept and early prototype

## What I Want To Learn

I want to learn what beginners need in a command-line lesson to understand where they are, make sense of the output, and recover when a command does not work.

## Current Hypotheses

- Learners may abandon tasks when they cannot determine their location, system state, or whether an action is reversible.
- Expected output and recovery guidance may be as important as the command itself.
- Feedback that explains cause and next action may improve recovery more than reassurance alone.
- Scaffolding should change with prior experience instead of treating all beginners alike.

These are starting assumptions, not conclusions.

## Why I Chose These Methods

| Method | Purpose |
| --- | --- |
| Recent-experience interviews | Understand real error, recovery, and abandonment episodes |
| Baseline task observation | Compare stated confidence with observable strategies |
| Prototype usability study | Evaluate lesson orientation, feedback, and recovery behavior |
| Delayed follow-up task | Test retention instead of relying only on immediate success |

## Sampling

I would recruit learners with basic HTML and CSS knowledge and limited-to-moderate terminal experience. The group would include self-taught learners, bootcamp students, and designers learning implementation. I would compare behavior by recent CLI use and would not treat confidence as proof of skill.

## Success Signals

- Participant explains a command’s purpose before running it.
- Participant distinguishes success, warning, and error states.
- Participant recovers from a planned error without moderator intervention.
- Participant completes a comparable task during delayed follow-up.
- Confidence change is reported alongside behavior, not as the sole outcome.

## What This Study Cannot Tell Me

Finishing a prototype lesson would not prove that someone learned the material. I would pilot the error task, run the main sessions, and use a comparable task one week later before making any claim about retention.
