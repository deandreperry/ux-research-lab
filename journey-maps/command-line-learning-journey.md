# Command-Line Learning Hypothesis Journey

- **Status:** Assumption map; stages and thoughts are not participant findings

The “Thoughts” entries are prompts for validation, not participant quotations.

## Scenario

A designer learning frontend development needs to use the terminal to run a local project and install dependencies.

## User Goal

Complete common command-line tasks without fear, understand command output, and recover from mistakes.

## Stages

| Stage | Actions | Thoughts | Pain Points | Opportunities | UX Recommendations |
| --- | --- | --- | --- | --- | --- |
| Orient | Opens terminal lesson and checks prerequisites. | "Am I in the right place?" | Terminal concepts like paths and folders may be unclear. | Build a simple mental model first. | Explain current directory, command, output, and prompt visually. |
| Execute | Runs first command. | "Did that work?" | Successful output may still look intimidating. | Show expected output. | Pair commands with example output and explanation. |
| Interpret | Reads logs, warnings, or errors. | "Is this bad?" | Warnings can be mistaken for failures. | Teach difference between success, warning, and error. | Label output types and likely next action. |
| Recover | Fixes path or install issue. | "Can I undo this?" | Fear of breaking something slows experimentation. | Normalize safe recovery. | Add reset steps and plain-language troubleshooting. |
| Apply | Runs project and connects CLI to browser result. | "Now I see why this matters." | Lessons can feel disconnected from visible outcomes. | Reinforce purpose. | Link terminal actions to product result or local preview. |

## UX Recommendations

- Use visual models to explain terminal state.
- Include expected output for every command.
- Teach recovery paths as part of the lesson, not as an appendix.
- Connect CLI actions to visible frontend outcomes.

## Validation Plan

Observe learners with varied recent CLI use in a safe sandbox. Record paths, predictions, errors, workarounds, help-seeking, recovery, and task transfer one week later. Add non-linear journeys for setup failure, external search, peer help, and abandonment when evidence supports them.
